# Tools used to build the 2026 decks

These are working scripts, not a polished pipeline. They are kept here so the
figures can be regenerated and the workflow resumed.

## Paths

Every deck lives in its own folder with only its own figures:
`Slides/NN-Name/ICSS-2026-NN-Name.qmd` with `Slides/NN-Name/figures/`, and the
example decks in `Slides/Examples/NN-Examples/`. The theme and the logo are
shared in `Slides/theme/`. Images that no deck uses are kept in
`Slides/unused/`, under their old paths.

All scripts write into `ICSS_2026/Slides/…` with absolute paths, and read the
2025 originals from `ICSS-local/Slides/`. They also use a scratch directory
under `/tmp` for intermediate files — adjust the constant at the top of
`deckprep.sh` and `build.sh` if that directory is gone.

## `deckprep.sh NN`

Unpacks one 2025 deck for inspection:

- `text.txt` — `pdftotext -layout` of the PDF (the fastest way to read a deck)
- `pages/p-NN.png` — every slide rendered at 72 dpi
- `pptx/` — the unzipped pptx, so `ppt/media/` has the original images
- `map.txt` — which image sits on which slide, with position and size in inches
- `montage.png` — contact sheet of all images, for identifying and renaming them

Use `map.txt` + `montage.png` together: the position/size tells you which slide
an image belongs to, the contact sheet tells you what it shows.

## `genNN.py`

Regenerates the SVG figures for one session into that deck's own folder,
`Slides/NN-Name/figures/`. Everything
is plain SVG written by hand-rolled helpers — no dependencies beyond Python.

Two of them are worth knowing about because the figures are **derived, not
drawn**:

- `gen05.py` holds the breadth-first-search trace as a state table; the graph,
  the distances, the parents and the queue in each figure all come from it.
- `gen07.py` actually **runs** heapsort (min-heap extract-min with sift-down)
  and emits one SVG per step, so the 31 trace figures cannot disagree with each
  other. `mk07.py` re-runs the same simulation to emit the captions.

## `mkNN.py`

Emits a whole `.qmd` for sessions whose decks are long and repetitive
(6 and 7). **The generated `.qmd` is the source of truth from now on** — edit
the `.qmd` directly. These are kept only to show how the repetitive slides were
produced and in case you want to regenerate from scratch.

## `build.sh BASENAME`

Renders a deck, prints it to PDF headlessly, and checks every page for content
running off the left/right edge or into the footer bar. Output:

```
pages: 78
overflow: none
```

`pages` must match the page count of the 2025 PDF — that is the check that no
slide was lost or accidentally split.

## Fit levels and the generated slides (2026-10-18)

The theme's base font is 37.5px. A slide whose content does not fit carries
`{.fit1}` to `{.fit4}` on its `##` heading (see the end of
`Slides/theme/unikn.scss`); `fit2` is the old 30px size.

The decks are the source of truth for their slides, including the
motivating-example slides that `genmotivation.py` once inserted: do not
re-run `genmotivation.py` on the decks, it would replace the edited slides.
The example decks are still generated by `genexamples.py`, which keeps the
fit classes of the existing deck when it regenerates one.

## Checking and sizing slides (2026-10-30)

- `measuredeck.py DECK.qmd [--render]` opens a rendered deck in headless
  Chrome in print mode and lists every slide whose content reaches the footer
  line, a page edge, the edge of its column, or sits in a code block that
  needs scrolling. A finished deck prints `overflow 0`.
- `fitcode.py DECK.qmd N [N ...]` makes the code on slides N as large as
  possible: it scales the `::: {style="font-size:…"}` wrappers of each slide
  by one factor, found by bisection with `measuredeck.py`.
- `gen04.py` draws the two software-engineering flow figures of session 4.
